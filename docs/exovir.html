Alur utama — sepuluh tahap

Pilih tahap untuk melihat input, metode, perangkat, output, validation gate dan cara implementasi.

Enam submesin analisis ilmiah korpus

Korpus dibangun, dihitung, dibaca, diuji, dan disaring secara dapat direproduksi.

Ketentuan korpus: 100 referensi bukan angka pembuktian novelty. EXOVIR harus melaporkan cakupan pencarian, status full-text, sumber indeks, potensi literatur yang terlewat, dan ketidakpastian.

Delapan pengujian novelty

Setiap pengujian memiliki pertanyaan, metode, keluaran bukti dan kondisi untuk melemahkan klaim.

Status keputusan ilmiah

Gugur

Studi terdahulu ekuivalen ditemukan dan klaim kebaruan tertentu terbantahkan.

Lemah / inkremental

Kontribusi berbeda, tetapi belum signifikan atau tidak menjawab masalah penting.

Bertahan sementara

Belum berhasil digugurkan pada cakupan yang diaudit; bukan pembuktian absolut.

Belum cukup bukti

Korpus, teks lengkap, mutu bukti atau pemeriksaan belum memadai.

Direktori tools AI dan cara integrasinya

REST API ≠ MCP ≠ aplikasi UI. Filter untuk mempelajari cara EXOVIR menghubungkan setiap perangkat.

Data diverifikasi dari dokumentasi produk

Penting: Verifikasi endpoint, fitur, izin, paket langganan, kuota, dan kebijakan redistribusi pada akun yang benar-benar akan dipakai. Tidak ada API key atau sesi vendor disimpan di HTML ini.

Implementasi teknis — EXOVIR backend

Pola integrasi yang dapat dibangun tanpa menggantungkan keseluruhan sistem kepada satu vendor.

Arsitektur layanan yang disarankan

FrontendWeb workspace

Profil, hibah, evidence matrix, graf, review, dan status gate. Meminta data ke backend EXOVIR.

API/orchestratorFastAPI atau Node

Auth, project state, eligibility engine, connector registry, task API, audit.

WorkersQueue + job runner

Pencarian, unduh, parsers, dedupe, ekstraksi, bibliometrik, kritik novelty, retry.

Evidence storePostgreSQL + pgvector

Paper, study, grant rules, claims, spans, embedding, keputusan dan versi.

Object storagePDF, RIS, CSV, grafik

Simpan hanya sesuai hak akses; hashes, provenance dan izin sumber.

GuardrailsRBAC & usage ledger

Server secrets, rate limit, budgets, monitoring, versioning dan sign-off manusia.

Kesalahan yang perlu dicegah

Jangan meletakkan API key pada HTML/GitHub Pages

GitHub Pages hanya cocok sebagai situs dokumentasi statis ini. Implementasi EXOVIR yang memanggil API memerlukan backend aman.

Jangan menyamakan job sukses dengan bukti ilmiah sukses

Gunakan tiga status terpisah: execution state, evidence readiness, scientific decision.

Jangan mengarang data dari abstrak

Jika artikel hanya tersedia metadata/abstrak, sel metode/hasil yang tak terakses tetap unknown.

Jangan menjanjikan semua API tersedia

Adapter bertanda verified hanya jika kontrak, izin, response schema dan test call sudah lulus pada akun riil.

Validasi dan acceptance test

Kriteria yang perlu disetujui sebelum EXOVIR mengeluarkan penilaian ilmiah final.

GateUjiBukti yang harus ada
R1 IdentitasDisambiguasi penelitiKarya benar, afiliasi, identitas konflik dan konfirmasi.
G1 HibahRule engine dan versi pedomanTRUE/FALSE/UNKNOWN setiap syarat wajib + sumber.
P1 MasalahKesesuaian sumber–indikator–populasiTahun data, status regulasi, penyebut statistik dan konteks.
C1 KorpusReproduksibilitas dan relevansiSearch log, count, source provenance, dedupe, screening.
C2 SubstansiKetepatan ekstraksiAudit sample human-verified, dukungan spans sumber.
N1–N8 NoveltyAdversarial benchmarkRecall prior art, false-pass novelty, audit disagreements.
M1 MetodeFeasibility stress testData, sampel, alat, bias, etik, biaya dan durasi.
F1 ProposalPedoman + referensi + sign-offMatriks patuh skema, audit sitasi, human approval.

Ambang numerik tidak ditetapkan sebagai angka karangan. Kalibrasikan menggunakan benchmark representatif dan penilaian ahli per bidang/skema.
